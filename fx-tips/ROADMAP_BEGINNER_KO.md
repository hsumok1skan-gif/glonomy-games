# FX Lab 성장 로드맵 · 초보 AI 게임 제작자를 위한 이펙트 도서관
> 2026-10-19 기준. 운영형 콘텐츠 백로그입니다. **미구현 아이디어를 구현 완료라고 표시하지 않습니다.**

## 1. 목표와 원칙

**사용자:** 게임 전문 개발자가 아니라, ChatGPT·Claude 등 AI와 함께 첫 게임을 만들거나 수정하는 사람.

**첫 방문 경험:** "이 효과 멋있다 → 내 게임에서도 써보고 싶다 → AI에게 구현을 요청할 수 있다."
**재방문 이유:** 발견할 만한 새 효과, 장르별 목록, 보관한 효과, 실전 적용 사례가 늘어난다.

**고정 원칙**
1. 기존 539개 레시피와 각 고유 ID는 삭제·덮어쓰기하지 않고 보존한다. 묶음 릴스는 별도 콘텐츠.
2. 화려함은 **눈에 띄는 게임 상황의 반응**이지 무조건 많은 파티클이 아니다.
3. RAW와 FINAL은 동일한 행동과 타이밍으로 비교하고, 연출의 원인을 단계별로 볼 수 있게 한다.
4. "코드 복사"와 "내 게임에 적용"을 혼동하지 않는다. 브라우저 JS 예제는 다른 엔진에 그대로 동작하지 않는다.
5. 사용자가 코딩을 모른다고 가정해 **한국어 설명**, 한 화면의 핵심 버튼 1개, 이해하기 쉬운 카테고리를 우선한다.
6. 모바일 UI는 PC 흐름과 분리해 개선한다. 9:16 녹화·효과음·기존 기능은 반드시 회귀 테스트.
7. 업로드와 공유는 소스·이미지·사운드 저작권을 확인한 후 진행한다.

## 3. 다음에 채울 콘텐츠 (효과 예제 중심)

**P1 — 첫 재방문을 만드는 소규모 큐레이션**
- **장르별 스타터 세트:** "AI로 처음 만드는 액션 게임 10개", "퍼즐 만들 때 반드시 필요한 10개", "RPG 보상 효과 10개", "모바일 터치 손맛 10개" — 기존 레시피를 선별하여 묶고 사용 맥락 설명.
- **잘 된 효과 전후 사례 12편:** 단순히 RAW/FINAL보다 "왜 훨씬 좋게 느껴지는지"를 2문장으로 설명.
- **내 게임에 어디에 쓰지?** 각 효과에 "추천 장면", "조합하면 좋은 효과 2개", "부하 주의사항" 3항목.
- **AI 요청문 4종:** 웹(HTML/JS), Unity, Godot, GDevelop/노코드. 엔진 변환 코드가 아니고 해당 도구에 맞춘 구현 *요청 템플릿*.
- **취향별 추천 5개:** 묵직함 / 귀여움 / 시원한 보상 / 긴장감 / 마법·판타지. 같은 장르라도 다르게 발견 가능.

**P2 — 보는 재미와 제작 도움을 강화하는 새 쇼케이스**
- **검 휘두르기 "맛" 세트:** 예비동작 → 궤적 → 타격 정지 → 충격파 → 적 반응.
- **총기 히트 세트:** 발사 반동 → 탄피 → 탄 궤적 → 피격 → 마지막 결정타.
- **마법 충전·발사:** 충전 입자 → 마법진 → 발사 → 도착 시 파열 → 화면 잔광.
- **퍼즐 연쇄 성공:** 1회 성공 → 연쇄 콤보 → 점수 팝업 → 큰 보상.
- **RPG 성장 보상:** 레벨업 → 전리품 → 레어 등급 → 장비 획득 → 스킬 해금.
- **UI 터치 완성:** 버튼 누름 → 저장 완료 → 퀘스트 알림 → 획득 팝업.
- **레이싱 스피드감:** 속도선 → 부스트 → 드리프트 → 구간 기록 → 결승.
- **생존 긴장감:** 체력 위험 → 긴급 경고 → 회피 → 회복/안전 지대.
- **호러와 환경:** 문 여는 순간, 손전등 깜빡임, 안개, 경보, 탐색 사운드. *과도한 플래시 주의*.
- **보스 처치 피날레:** 실루엣 → 피격 정지 → 부서짐 → 보상 공개.

*제작 기준:* 모든 세트는 9:16으로 녹화 가능한 시연, RAW/FINAL, 짧은 한국어 설명, 실제 동작하는 예제/코드 링크, AI 요청문 제공.

**P3 — 사용자가 자발적으로 공유하는 사례**
- "이 효과로 만든 내 게임": 제출자의 허락을 받은 링크·영상·사용 엔진·사용한 FX 표시.
- "1분만에 바꾸기" 튜토리얼: 클릭 3단계 + AI 요청문 + 전후 영상.
- "이번 주의 FX": 5개 큐레이션 묶음. 매일 539개를 새로 찍어야 한다는 압박을 줄임.
- "FX 조합 추천": 예컨대 **대시 + 잔상 + 착지 먼지**를 하나의 움직임으로 시연.
- 커뮤니티 제보: 새로운 효과를 투표받되 스팸·저작권·품질 관리 체계 마련 후.
- 엔진별 실전 사례: 사용자가 허락한 Unity/Godot/웹 프로젝트 예제만 표시.

## 6. 2~4주마다 반복할 작은 배포 과정

1. 실제 사용하는 사람(우선 제작자 본인)이 "이 장면 심심하다"라는 사례 3개를 모은다.
2. **기존 539개 검색 → 기존 효과로 해결 가능하면 새 효과 추가 대신 큐레이션/개선.**
3. 재미있는 순서대로 **2~5개만** 만든다. 완성도 기준에 못 미치면 게시하지 않는다.
4. 9:16 시연, RAW/FINAL, 소리, AI 요청문, 원본 코드 복사, 모바일 성능 테스트.
5. 수정 브랜치 → 미리보기 → 539개 보존/JS 검사 → 수동 재생 → 운영 반영.
6. 저장 기능·검색·완성 미리보기 중 실제로 많이 쓰이는 흐름을 관찰한다. 수집할 통계가 필요하면 개인정보 보호를 먼저 설계한다.
7. 이 문서의 상태와 다음 우선순위를 갱신한다.
